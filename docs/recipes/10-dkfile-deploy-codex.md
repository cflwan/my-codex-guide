# 用 DKFile 一键发布网页到公网

## 这案例干啥的

就是你本地写了个网页(HTML/CSS/JS),想让 Codex 帮你发到公网上,别人能直接访问。不用自己搭服务器、配域名、搞 HTTPS,一条命令搞定。

相当于给你的本地页面开了个公网入口。

## 啥时候用

- 写了个 demo 想给同事看,但对方不在同一网络
- 做了个静态页面想快速预览效果
- 需要给别人看个临时页面,不想正经部署
- 给客户演示原型,得有个能点的链接

## 准备工作

- Codex 配好 DKFile 能力(或者类似的发布工具)
- 本地有要发布的静态文件(HTML、CSS、JS,准备好 index.html)
- 网络能通,能访问 DKFile 服务
- 大概知道发布后想用多久(临时还是长期)

## 怎么搞

### 第一步:准备文件

把你要发布的网页放到一个目录里,确保有 index.html。比如:

```
my-demo/
├── index.html
├── style.css
└── script.js
```

### 第二步:告诉 Codex

进到这个目录(或者跟 Codex 说路径),让它发布:

> 把当前目录下的静态网页发布到公网,我要一个能访问的链接。发布完告诉我访问地址。

### 第三步:AI 调用 DKFile

Codex 会:
1. 扫描目录,确认有 index.html
2. 调用 DKFile 上传文件
3. 拿到一个公网 URL

### 第四步:拿链接

AI 会返回一个类似 `https://xxx.dkfile.app/yyy` 的链接,这就是公网地址。

### 第五步:测试访问

把链接发给别人,或者自己用手机打开,看能不能正常显示页面。

### 第六步:管理(可选)

如果 DKFile 支持"下线"操作,跟 Codex 说:

> 把之前发布的那个 demo 下线,链接不用了。

## 验证结果

- 拿到了一个 https 开头的公网链接
- 用浏览器(最好换设备、换网络)能打开
- 页面内容、样式、交互都正常
- 链接可以分享给别人访问

## 注意事项

::: tip
发布前检查下:别有敏感信息(API key、密码、内部数据)。一旦发到公网,谁都能看到。临时 demo 用完记得下线。
:::

::: warning
这种快速发布服务通常有流量、容量限制,别拿来正经部署业务。正经项目还是上正经服务器或者 Vercel/Netlify 这类。
:::

## 我的经验

我用这个的场景:写完一个前端 demo,直接发出去给设计同学在真机上看效果。比让对方跑本地快太多了。

还有个用法--写文档站点(MkDocs、VitePress 之类的),build 完直接发出去,团队共享。比配 GitHub Pages 还快。
