# 任务执行与验证闭环

## 别盲信 AI

Codex 很强，但它会犯错。**每次任务完成后，你必须验证结果。**

## 验证三步法

### 第一步：看它做了什么

Codex 完成任务后会告诉你它做了啥：
- 改了哪些文件
- 加了什么、删了什么
- 跑了什么命令

**先看它的报告**，别急着用。

### 第二步：自己检查

打开文件看看实际改了什么。

- 代码逻辑对不对
- 有没有多余的改动
- 代码风格一致不一致
- 有没有引入错误

### 第三步：跑验证

如果你有测试，跑一遍：

```bash
# Java 项目
mvn test

# Node 项目
npm test

# 或者手动验证
mvn compile  # 能编译不
```

## 什么时候追问

遇到这些情况，继续追问 Codex：

- 它改了你没让它改的文件
- 代码能跑但逻辑不对
- 它说"完成"但测试没过
- 它引入了你没见过的新依赖
- 它删除了看起来很重要的代码

## 什么时候停止

遇到这些情况，停下来：

- 它改了不该改的东西（数据库表结构、配置文件）
- 来回改了三次还是不对
- 它开始"猜"你要什么
- 你自己都不知道想要什么

## 闭环流程

```text
描述任务 → Codex 执行 → 看报告 → 检查代码 → 跑测试
  ↑                                                    ↓
  ←←←←← 不满意，告诉它哪里不对 ←←←←←←←←←←←←←←←←←←←← 满意
                                                        ↓
                                                     完成 ✅
```

## 我的经验

::: tip
Codex 不是你老板，你是它老板。它干完了你检查，不满意就让它改，改不好就撤销重来。

别被"AI 说的"吓住，它说的不一定对。
:::
